Capstone 2 — Quick Reference

Kalubihan Emergency Response System

All system features and the technology framework — print or keep open during the defense.

Main framework: React 18 (frontend, single-page app) + Supabase (backend — PostgreSQL, auth, storage, realtime, edge functions; no custom server).

User Roles

Resident

  • Register with valid ID upload — OCR reads it automatically
  • Can only report after admin approves their ID
  • Files reports: 8 incident types, photo required, GPS auto-pinned
  • Tracks report status + gets notifications and announcements

Dispatcher

  • Live incident queue on a map — sees clustered duplicates
  • Sets priority, assigns the primary department
  • Assigning a department auto-sends help requests to the assisting team

Department Admin (per team)

  • Own department queue only
  • Assigns a specific responder/unit to the incident

Responder

  • Sees assigned incidents + assistance requests
  • Accept → arrive on scene → resolve with proof photo
  • Marked busy while on an open incident

Admin

  • Resident ID verification queue — approve/reject
  • User & role management, department management
  • Metrics dashboard + exportable incident records
  • Edits the service boundary on a map

The 3 Barangay Teams

  • Disaster Response Team (BDRRMC) — flood, fire, fallen structures
  • Barangay Tanod / Peace & Order — theft, assault, disturbances
  • Health & First Aid Team — medical, road accidents
  • BFP / PNP / DRRMO shown as "coordinate with" guidance — outside agencies, not in-app

Core Features

Integrity & Security

  • Row-Level Security — DB rules decide what each role sees
  • Geofence — out-of-barangay reports rejected server-side
  • Photo evidence — required, enforced by DB trigger
  • ID verification gate — unverified residents cannot report
  • Passwords hashed by Supabase Auth (bcrypt + JWT sessions)

Smart Dispatch

  • Auto-assistance — assigning a main team fires help requests to the second team (e.g., accident → Health + Tanod)
  • Incident clustering — same-type reports within 150m auto-group; status propagates to all members
  • Response guide — every report shows which teams respond + which outside agency to call

Communication

  • Realtime updates — boards refresh live, no polling (Supabase Realtime)
  • Email notifications — approval, resolution, suspension (Resend API via Edge Functions)
  • Announcements feed — barangay-wide broadcasts

Records

  • Full audit trail — who reported, assigned, responded, resolved
  • Metrics & analytics dashboard (Recharts)
  • Exportable incident records for accountability

Framework & Stack

Frontend

  • React 18 + Vite 5 — single-page app, role-based portals
  • Tailwind CSS 3.4 — responsive, mobile-first styling
  • React Router 6 — routing  ·  Redux Toolkit — auth/session state
  • Leaflet + OpenStreetMap — maps, free & keyless
  • Recharts — analytics  ·  framer-motion + lucide — UI polish
  • tesseract.js — client-side OCR for ID extraction (privacy)

Backend — Supabase

  • PostgreSQL — relational DB, triggers enforce the rules
  • PostgREST — auto-generated REST API on the schema
  • Supabase Auth — login, bcrypt hashing, JWT sessions
  • Storage — ID photos & evidence, policy-gated buckets
  • Realtime — Postgres replication pushes changes to boards
  • Edge Functions (Deno) — server-only logic holding secrets

Edge Functions

  • broadcast-incident — pushes new incident alerts
  • notify-decision — verification approve/reject email
  • notify-resolved — resolution notice to resident
  • notify-suspension — account suspension notice
  • verify-id — server-side ID check support

External APIs & Deployment

  • Resend — transactional email
  • OpenStreetMap tiles — map rendering
  • Browser Geolocation API — GPS capture
  • Frontend: Vercel (static build) + Supabase cloud backend
  • Tests: Playwright e2e + live-DB regression scripts
One-liner if asked "why this stack": "Supabase gives us database, auth, storage, realtime, and server functions in one — no custom server to build or maintain, and the database itself enforces the security rules."
