Database Design

Entity Relationship Diagram

Figure 49: Entity Relationship Diagram

The Entity Relationship Diagram (ERD) of the Kalubihan Emergency Response System showcases a relational structure built on Supabase (PostgreSQL) to manage emergency reporting and user roles efficiently. At the center is the user_profiles table, which links to auth.users for login credentials and stores the role classification—whether the user is an Admin, Dispatcher, Responder, Resident, or Department Administrator—along with the account status and approval fields that gate platform access. The id_verifications table is responsible for validating user identity documents before full access is granted, while departments organizes responders and department administrators by service type.

The emergency_reports table handles all submitted emergency reports and connects with several key entities: user_profiles (reporter, assigned responder, and backup responder), departments (assigned unit), and incident_media (visual proof of the incident). Each report carries a status, priority, location, and coordinates. Activity around a report is captured by report_updates, incident_status_history, and incident_messages, while notifications keep every role informed. This structure ensures that emergency cases are not only documented but are traceable, verifiable, and organized for quick response.

Departmental coordination is handled through cross_department_assistance, responder_backup_requests, and reassignment_requests, which let departments request help or re-route incidents between units. Responder field positions are tracked in responder_locations, and resident contacts are stored in emergency_contacts alongside the public directory in department_contacts. Advisory broadcasts live in announcements. The audit_logs table further enhances accountability by tracking user actions and their timestamps, page_permissions drives the role-based access matrix, and geofence_boundaries stores the service-area polygon used to validate report locations. Together, these entities form a robust, role-based emergency management system capable of handling real-time data, securing user validation, and ensuring proper departmental response to emergencies.
